# ✏️ 텔레스트레이션 (온라인 실시간)

각자 폰이나 PC로 **4자리 방 코드**를 입력해 들어와서, 그림과 추측을 번갈아 가며 스케치북을 돌리는 온라인 텔레스트레이션입니다.
빌드 도구 없이 **순수 HTML/CSS/JS(ES 모듈)** 로 작성했고, 실시간 동기화는 **Firebase Realtime Database**, 배포는 **Firebase Hosting**을 씁니다.

## 수업 모드 (선생님용)

수업에서 쓸 때는 **선생님 화면**(`/teacher.html`, 첫 화면 아래 "👩‍🏫 선생님용 화면" 링크)에서 방을 엽니다. 선생님은 플레이하지 않고 진행만 합니다.

1. **수업 코드**(예: `3반`)와 **비밀번호**로 들어갑니다. 처음 쓰는 코드면 새 수업이 만들어지고, 다음 수업부터는 같은 코드·비밀번호로 다시 들어오면 됩니다. 같은 브라우저라면 자동으로 로그인돼요.
2. **수업 설정**: 모둠 수(1~8), 그리기·추측 시간, 제시어 목록(한 줄에 하나, 비우면 기본 제시어). 바꾸면 자동 저장되고, 게임 시작 때는 화면에 적힌 값이 그대로 쓰입니다. 수업 방에서는 인원이 홀수든 짝수든 학생마다 이 목록에서 무작위로 나온 3개 중 하나를 골라 시작합니다(직접 쓰기 없음).
3. **모둠 방 열기** → `3반-1`, `3반-2` … 모둠 방이 한 번에 열립니다.
4. 학생은 사이트에 들어와 **이름 + 수업 코드**를 입력하고 **자기 모둠 번호**만 누르면 됩니다. 학생용 링크(`?class=3반`)를 복사해 나눠 줘도 돼요.
5. 모둠별 카드에서 참가자 확인·내보내기(✕)·시작을 하거나(게임 중에는 아직 안 낸 학생과 연결 끊긴 학생이 카드에 표시돼요), **모든 모둠 시작**으로 한꺼번에 시작합니다. 수업 모둠은 3명부터 시작할 수 있습니다.
   - **모둠장 시작**: 각 모둠에 가장 먼저 들어온(지금 접속 중인) 학생이 👑 모둠장이 되어 자기 화면의 **게임 시작**으로 시작할 수 있습니다. 모둠장이 누르면 선생님 화면이 선생님 제시어·시간 설정으로 시작합니다(선생님 화면이 켜져 있어야 함). 설정의 체크박스로 끌 수 있어요.
   - **👀 들여다보기**: 모둠 카드에서 누르면 그 모둠 학생별 상태(그리는 중·맞히는 중·냈어요·연결 끊김)와 **그리는 중인 그림 미리보기**(3초마다), 지금까지 낸 스케치북 페이지를 한눈에 봅니다. 미리보기는 선생님이 이 화면을 열어 둔 모둠만 올라와요(데이터 절약).
   - **⚠️ 경고**: 학생 화면에 선생님 알림 창을 띄웁니다(문구 수정 가능).
   - **🙈 가리기**: 장난친 그림·답을 지웁니다. 다음 사람에게는 "선생님이 가렸어요"로 보이고 결과 발표에도 나오지 않아요(되돌릴 수 없음).
   - **🚫 강퇴**: 학생 화면이 첫 화면으로 나가고, **모둠 방을 새로 열 때까지** 그 모둠에 다시 못 들어옵니다(같은 이름으로도). 게임 중이면 자리는 남겨 두고 남은 차례는 연결 끊긴 학생처럼 건너뛰어 스케치북 순서가 깨지지 않아요.
6. 게임이 끝나면 학생들은 각자 친구들의 스케치북을 넘겨 보고 **✅ 준비 완료**를 누릅니다. 접속 중인 학생이 모두 준비되면 **모둠장에게 "다음 판 시작"** 버튼이 생기고, 누르면 선생님 제시어·시간 설정으로 다음 판이 시작됩니다(선생님 화면 모둠 카드의 **▶ 다음 판**으로도 시작 가능). 모둠 카드에는 준비 인원이 표시돼요.
   - **결과 발표**로 전자칠판/TV에 띄우고 한 장씩 넘길 수도 있습니다. 학생이 **📺 발표 따라가기**를 누르면 선생님 화면을 따라 넘어갑니다.
7. 끝나면 **수업 끝내기**로 모둠 방을 닫습니다.

- 게임 진행(라운드 넘기기)은 선생님 화면이 담당하므로 **수업 중에는 선생님 화면을 켜 두세요.** 잠시 닫혀도 다시 열면 이어서 진행됩니다.
- 비밀번호는 저장하지 않고 `수업코드:비밀번호`의 SHA-256만 보안 규칙이 서버에서 비교합니다. 학생이 수업 코드를 알아도 비밀번호 없이는 선생님 화면을 쓸 수 없고, 모둠 방의 진행권도 가져갈 수 없습니다.
- 비밀번호를 잊으면 Firebase 콘솔 → Realtime Database에서 `classSecrets/<수업코드>`, `ownerClaims/<수업코드>`, `classes/<수업코드>`를 지우고 새로 만드세요.

## 게임 규칙

- 4~10명. 플레이어가 N명이면 스케치북도 N권, 라운드도 N번입니다. 매 라운드 모든 스케치북이 한 칸씩 옆으로 넘어갑니다.
- 모든 스케치북의 마지막 페이지가 '추측'으로 끝나도록 원작의 홀수/짝수 규칙을 따릅니다.

| 인원 | 1라운드 | 이후 | 마지막 페이지 |
| --- | --- | --- | --- |
| 짝수 (4, 6, 8…) | 자기 제시어를 그림으로 (랜덤 3개 중 고르거나 직접 쓰기) | 추측 → 그림 → 추측 … | 추측 |
| 홀수 (5, 7, 9…) | 자기 제시어를 글로 적기 | 그림 → 추측 → 그림 … | 추측 |

- 각자 받은 스케치북의 **바로 앞 페이지만** 보고 그리거나 추측합니다.
- '완료'를 누르거나 시간이 끝나면 제출됩니다. 시간이 끝나면 그때까지의 그림이나 빈 답이 자동 제출됩니다.
- 전원이 제출하면 마감 전이라도 다음 라운드로 넘어갑니다.
- 끝나면 스케치북을 한 권씩, 한 장씩 넘겨 봅니다. 방장이 넘기면 모두의 화면이 같이 넘어갑니다(발표 모드). '혼자 넘겨 보기'도 됩니다.

기본 시간은 그리기 60초, 추측 30초이고 로비에서 방장이 바꿀 수 있습니다. 짝수 인원 1라운드는 제시어를 고르는 시간으로 15초를 더 줍니다.

## Firebase 준비 (최초 1회)

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트를 만듭니다.
2. **Authentication → 로그인 방법 → 익명**을 사용 설정합니다.
3. **Realtime Database → 데이터베이스 만들기** (위치는 `asia-southeast1` 추천, 잠금 모드로 시작해도 됩니다. 규칙은 아래에서 배포합니다).
4. **프로젝트 설정 → 내 앱 → 웹 앱 추가** 후 표시되는 설정값을 `js/firebase-config.js`에 붙여 넣습니다. `databaseURL`도 꼭 넣어야 합니다.
5. `.firebaserc`의 `YOUR_PROJECT_ID`를 내 프로젝트 ID로 바꿉니다.

## 배포

### 자동 배포 (GitHub Actions)

`main`에 푸시하면 `.github/workflows/deploy.yml`이 호스팅과 보안 규칙을 배포합니다. 처음 한 번만 설정하면 됩니다.

1. [Google Cloud 콘솔 → IAM → 서비스 계정](https://console.cloud.google.com/iam-admin/serviceaccounts)에서 Firebase 프로젝트를 선택하고 서비스 계정을 만듭니다. 역할은 **Firebase 관리자(Firebase Admin)** 를 줍니다.
2. 그 서비스 계정의 **키 → 키 추가 → JSON**으로 키 파일을 내려받습니다.
3. GitHub 저장소 **Settings → Secrets and variables → Actions → Secrets**에 `FIREBASE_SERVICE_ACCOUNT` = JSON 파일 내용 전체를 넣습니다.
   (배포 대상은 `.firebaserc`의 프로젝트입니다. 다른 프로젝트로 보내려면 Variables에 `FIREBASE_PROJECT_ID`를 지정하세요.)
4. **Actions → Deploy to Firebase → Run workflow**로 실행하거나 `main`에 푸시합니다.

### 수업 데이터 (`data/classes.json`)

선생님이 만든 수업 목록·설정·제시어는 저장소의 `data/classes.json`에도 둡니다. 목록 보기: `npm run classes`

```jsonc
{
  "2727": { "groups": 6, "leaderStart": true, "settings": { "drawSec": 60, "guessSec": 30 }, "words": ["입춘", "우수"] }
}
```

- **저장소 → Firebase**: 이 파일을 고쳐 `main`에 푸시하면 배포 워크플로가 파일에 적힌 수업의 `groups`·`leaderStart`·`settings`·`words`를 Firebase에 덮어씁니다. 파일이 바뀐 푸시(또는 수동 실행)일 때만 반영하므로, 코드만 고친 푸시는 선생님 화면에서 바꾼 설정을 건드리지 않습니다. `words`를 `[]`로 두면 기본 제시어를 씁니다.
- **Firebase → 저장소**: 선생님 화면에서 바꾼 내용은 **Actions → Export classes from Firebase**(매일 03:00 자동, 수동 실행 가능)가 이 파일로 커밋해 가져옵니다. 파일을 고치기 전에 한 번 돌리거나 `git pull` 하세요.
- 파일에 새 수업 코드를 추가하면 비밀번호 없이 만들어지고, **처음 로그인한 선생님의 비밀번호**로 정해집니다. 파일에서 수업을 지워도 Firebase의 수업은 지워지지 않습니다(콘솔에서 삭제).
- 비밀번호·진행 상태(`open`·`openedAt`)·게임 기록(`rooms`)은 저장소에 올리지 않습니다.

### 직접 배포

```bash
npm install -g firebase-tools   # 한 번만
firebase login
firebase deploy                 # 보안 규칙 + 호스팅을 함께 배포
```

배포 후 `https://<프로젝트ID>.web.app` 으로 접속합니다. 로비의 **초대 링크 복사**를 누르면 `?room=ABCD` 가 붙은 링크가 복사되고, 그 링크로 들어오면 코드가 자동으로 채워집니다.

## 로컬에서 실행하기 (에뮬레이터)

실제 Firebase 프로젝트 없이도 로컬 에뮬레이터로 돌려 볼 수 있습니다. (Java 11+ 필요)

```bash
npm install          # 개발 도구(firebase-tools 등)만 설치. 앱 자체는 설치할 것이 없습니다.
npm run emulators    # Auth(9099) · Database(9000) · Hosting(5000)
```

- `http://127.0.0.1:5000/?emulator=1` 로 접속하면 에뮬레이터에 연결됩니다.
- 한 브라우저에서 여러 명을 테스트하려면 `?emulator=1&multi=1` 을 붙이세요. 탭마다 다른 익명 사용자가 됩니다.
  (주소에 `multi`가 없으면 같은 브라우저의 탭은 모두 같은 사람으로 취급됩니다.)

## 테스트

```bash
npm test             # 스케치북 로테이션·페이지 종류 규칙 (N=3~12)
npm run test:e2e     # 에뮬레이터를 켠 상태에서: 5명·4명·중간 이탈·수업 모드·재접속·관찰/제재 시나리오를 브라우저로 끝까지 진행
```

E2E는 방 만들기 → 입장(3명일 때 시작 불가, 게임 중 신규 입장 차단) → 설정 변경 → 전 라운드 진행(시간 초과 자동 제출, 새로고침 후 복귀, 게임 중 이탈) → 결과 발표 모드 동기화 → 방장 이탈 시 위임 → 로비 복귀까지 확인합니다.
Chromium 경로가 따로 있다면 `CHROME_PATH=/path/to/chrome` 을 지정하세요.

## 설계 메모

### 데이터 구조

방 하나가 `rooms/{방코드}` 노드 하나이고, 모든 클라이언트는 이 노드를 구독해 화면을 그립니다.

```jsonc
rooms/ABCD: {
  "hostId": "uid_a",
  "phase": "lobby | playing | result",
  "createdAt": 1790000000000,
  "settings": { "drawSec": 60, "guessSec": 30 },
  "players": { "uid_a": { "name": "덕환", "online": true, "joinedAt": 1790000000000 } },
  "order": ["uid_a", "uid_b", "uid_c", "uid_d"],
  "round": 2,
  "roundKey": "2",                       // 보안 규칙 비교용 (키는 문자열이라서)
  "assign": { "uid_a": "2", "uid_b": "3" }, // 이번 라운드에 각자 쓸 스케치북 번호 (보안 규칙용)
  "deadline": 1790000060000,
  "books": {
    "0": {
      "owner": "uid_a",
      "choices": ["고양이", "로켓", "피자"],   // 짝수 인원일 때 랜덤 제시어 후보
      "word": "고양이",                        // 짝수 인원 0라운드 제시어
      "pages": {
        "0": { "by": "uid_a", "type": "draw", "content": "data:image/webp;base64,..." },
        "1": { "by": "uid_d", "type": "guess", "content": "고양이" }
      }
    }
  },
  "submitted": { "2": { "uid_a": true, "uid_c": true } },
  "resultView": { "book": 0, "step": 3 },  // 발표 모드에서 방장이 보고 있는 위치
  "ready": { "uid_a": true },              // 결과 화면 '준비 완료'
  // 수업 방만
  "watch": true,                           // 선생님이 들여다보는 중 → 학생이 미리보기를 올림
  "banned": { "uid_c": "민수" },
  "warn": { "uid_b": { "at": 1790000070000, "msg": "제대로 참여해 주세요!" } },
  "rejoin": { "uid_new": { "name": "지우", "at": 1790000080000 } }
}
live/3반-1/uid_a: { "img": "data:image/jpeg;base64,...", "r": 2, "at": 1790000065000 }  // 선생님만 읽음
```

### 스케치북 로테이션

게임 시작 때 `order`를 섞어 고정하고, `order[i]`가 i번 스케치북의 주인입니다.
r라운드(0부터)에 i번째 플레이어는 `book(i, r) = (i - r + N) mod N` 스케치북의 r번 페이지를 씁니다.
따라서 0라운드는 주인이, 마지막 라운드는 주인 바로 앞 순번이 채웁니다.

### 실시간 동기화와 예외 처리

- 라운드 진행은 **방장 클라이언트 한 곳에서만** 결정합니다. 시간은 기기 시계가 아니라 Firebase 서버 시각(`.info/serverTimeOffset`) 기준 `deadline`으로 맞춥니다.
- 그림은 제출할 때만 `toDataURL('image/webp', 0.7)`로 저장합니다(획 단위 실시간 전송 없음). webp 인코딩을 못 하는 구형 Safari는 jpeg로 대체합니다.

| 상황 | 처리 |
| --- | --- |
| 라운드 시간 초과 | 각 클라이언트가 마감 시각에 현재 그림/입력값을 자동 제출, 방장은 2초 유예 후 다음 라운드로 |
| 전원 제출 완료 | 온라인 플레이어 전원이 제출하면 방장이 즉시 다음 라운드로 |
| 게임 중 이탈 | `onDisconnect`로 `online: false`와 끊긴 시각 `offAt`을 기록. 끊긴 지 10초 안이면 (마감 전까지) 돌아오길 기다리고, 그 뒤엔 해당 페이지를 "(건너뜀)"으로 채움. 스케치북 순서는 유지 |
| 제시어 고를 차례에 이탈 | 후보가 있으면 첫 번째 후보로 채워 다음 사람이 빈 제시어를 받지 않음 |
| 같은 이름 | 같은 방(모둠)에 같은 이름으로는 들어올 수 없음 |
| 새로고침·재접속 | 익명 uid가 같으므로 그대로 복귀, 현재 라운드 화면부터 이어서 |
| 탭을 닫았다가 수업 링크로 재입장 | 게임 중이어도 원래 있던 모둠 버튼은 열려 있어(`다시 들어가기`) 그 자리로 복귀 |
| 기기·브라우저가 바뀌어 다른 사람으로 인식 (카톡 링크 → 다른 브라우저 등) | 수업 방에서 같은 이름으로 들어오면 `rejoin/{새uid}` 요청 → 선생님 화면이 이름이 같고 **연결이 끊긴** 자리를 새 uid로 옮김(순서·배정·쓴 페이지·제출 기록 모두). 접속 중인 이름은 가로챌 수 없고, 선생님 화면이 켜져 있어야 함 |
| 장난치는 학생 | 선생님 들여다보기에서 경고(`warn`)·가리기(`hidden`)·강퇴(`banned`) |
| 그리다가 튕김 | 제출 전 획을 `localStorage`(`tele.draft.*`)에 저장해 두었다가 돌아오면 되살림. 제출하거나 게임이 끝나면 삭제 |
| 태블릿 화면 꺼짐 | 방에 있는 동안(선생님 화면 포함) Screen Wake Lock으로 화면을 켜 둠 (지원하지 않는 브라우저는 그대로) |
| 선생님 화면 꺼짐 | 게임 중에 닫으려 하면 경고. 마감 후 6초가 지나도 안 넘어가면 학생 화면에 "선생님께 알려 주세요" 안내, 다시 열면 이어서 진행 |
| 결과 화면 → 다음 판 | 각자 결과를 보고 `ready`를 누름. 접속 중인 전원이 준비되면 방장(수업 방은 모둠장)에게 '다음 판 시작'. 수업 방은 시작 요청을 선생님 화면이 받아 선생님 설정으로 시작 |
| 방장 이탈 | 남은 온라인 플레이어 중 `joinedAt`이 가장 빠른 사람이 `hostId`를 넘겨받음 |
| 게임 중 신규 입장 | 불가 (로비에서만 입장) |
| 중복 제출·지난 라운드 쓰기 | 페이지 경로가 `books/{b}/pages/{r}`로 고정이라 덮어쓰기만 됨, 지난 라운드는 보안 규칙으로 차단 |

### 보안 규칙 요약 (`database.rules.json`)

- 로그인한 사용자만 방을 읽고 쓸 수 있고, 방 목록 전체는 읽을 수 없습니다.
- `players/{uid}`는 본인만 수정, 새 입장은 로비일 때만.
- `phase`·`round`·`deadline`·`order`·`settings`·`resultView`는 `hostId`만 수정.
- 페이지는 `by`가 본인 uid이고, **현재 라운드**이며, **이번 라운드에 배정된 스케치북**일 때만 쓰기 허용.
- `hostId`는 현재 방장이 바꾸거나, 방장이 오프라인일 때 온라인 참가자가 자기 자신으로만 바꿀 수 있습니다.
- 수업 모드: `classSecrets`(비밀번호 해시, 아무도 읽을 수 없음)와 같은 해시를 쓴 사람만 `ownerClaims`에 등록되고, 등록된 선생님만 수업 설정·모둠 방 열기/닫기·진행을 할 수 있습니다. 수업 방의 진행권은 학생에게 넘어가지 않습니다.
- 방장(선생님)은 대기실에서 참가자를 내보낼 수 있습니다.
- `banned/{uid}`(강퇴)는 선생님만 쓰고, 강퇴된 학생은 자기 자리·페이지·시작 요청·미리보기를 쓸 수 없습니다. 같은 이름 입장은 앱에서 막습니다.
- `ready/{uid}`(결과 화면 준비 완료)는 결과 화면일 때 참가자 본인만, `rejoin/{uid}`(자리 되찾기 요청)는 수업 방에 아직 자리가 없는 본인만 쓸 수 있습니다.
- `live/{방}/{uid}`(그리는 중 미리보기, 60KB 미만)는 그 방 참가자 본인만 쓰고 **그 수업 선생님만 읽습니다.** 학생들이 구독하는 방 데이터 밖에 두어서 모둠원끼리 서로의 미리보기를 받지 않아요.
- 수업 방의 `startRequest`(모둠장 시작 요청)는 선생님이 `classes/<수업코드>/leaderStart`를 켰을 때만, 대기실에서, 그 방 참가자가 자기 이름으로만 쓸 수 있습니다.
- 12시간이 지난 방 코드는 새 방으로 덮어쓸 수 있습니다(오래된 방 정리). 데이터를 완전히 지우려면 콘솔에서 `rooms`를 주기적으로 비우거나 Cloud Functions 예약 함수를 추가하세요.
